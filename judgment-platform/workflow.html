🔎   What Happens at Each Stage
📄
PDF Upload & Storage
Steps 1 — FastAPI /upload endpoint
User drags & drops any court judgment PDF
File is saved to server upload directory
Case record is created in SQLite / Supabase
A unique Case ID is returned to the frontend
SSE stream starts to show processing progress
🔍
Text Extraction & OCR
Steps 2 — pdf_service.py
pdfplumber extracts raw text from digital PDFs
If text < 50 chars, OCR mode auto-activates
pdf2image converts each page to an image
pytesseract runs OCR on each scanned page image
All pages are stitched into a single text block
🧠
Agentic AI Analysis
Steps 3 — ai_service.py + groq_service.py
Full text is sent to LangChain with system prompt
Groq (Llama 3.3 70B) reads the entire judgment
AI returns a strict JSON with header, metrics, steps
Each workflow step has source_page & key_extract
Fallback: Google ADK / Gemini if Groq fails
📊
Dashboard — 4 Tabs
Steps 4 — WorkflowScreen.jsx
Workflow: AI action plan with deadlines & owners
Evidence: Relief items & key facts extracted
Timeline: Chronological compliance dates
Audit: Plain-language court directive summary
AI Chat panel for RAG-based Q&A on the judgment
✅
Human Verification
Steps 5 — review router + Role-Based Access
Legal Reviewer reads each AI-generated step
Clicks Approve ✅ or Reject ❌ on each step
Dept Officer role is blocked from approving
Approved steps are saved to database permanently
Final verified data feeds the Approved Dashboard
💬
RAG Q&A Chat
POST /cases/{id}/ask — ChatPanel.jsx
User types a question about the uploaded judgment
ChromaDB finds the most relevant text chunks
LlamaIndex retrieves and ranks source paragraphs
Groq answers using ONLY the source document text
Every answer is traced back to a specific page number
